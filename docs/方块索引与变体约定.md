# 方块索引与变体约定

## 原则

| 情形 | 做法 |
| --- | --- |
| 同一玩法、仅机型 / 朝向等细差（例：高级抓取机 / 抓取阀 / 分拣机） | **同一 Index**，用 Data 位区分 |
| 形态或职责不同（立方体存储 vs 定向 Transfer / 抓取机） | **各自独立方块类型**（各自 Index） |
| 新立方体 / 普通方块 Index | 对齐 SCIENEW：`public static int Index = N;` + `IsIndexDynamic => false`（N 用 500+ 空号）；地形判定用 `Blocks[contents] is T` |

混用的代价：`IsXxx(value)` 分支膨胀、CSV / 掉落 / 创造栏 / 实体模板纠缠，后期拆库成本高。贴图可以共用 `Assets/Logistics.png`，不必为此合并方块类。

## 当前方块

| Index | 类 | 形态 | Face / 图集 |
| --- | --- | --- | --- |
| 551 | `AdvancedLogisticsDeviceBlock` | 高级物流设备；Data bit0-2 为朝向，bit3-4 为机型（0 抓取机，1 抓取阀，2 分拣机）；具体机器由 `AdvancedLogisticsDeviceDefinition` 派生类承载 | 抓取机/抓取阀用模型 UV；分拣机为物流图集 cube，顶/底 5，侧面 1-4（红黄绿蓝对应 face 0–3） |
| 552 | `LogisticsStorageUnitBlock`（同 `BaseNormalBlock`：`static int` + `IsIndexDynamic => false`） | 不透明 `CubeBlock`，六面无缝 CT；簇共享储存库 | 运行时变体图集（底 **8** + 边 **5**，厚 2）；手持槽 0xFF；debris 源图集格 5 |
| 553 | `ConveyerBeltBlock` | 输送带；Data bit0-1 `rotation`，bit2 `shape`，bit3 `reverse`（Sign），bit4 `powered`（静/滚动半区）；邻接自动朝向只改 shape/rotation | 模型 + 全局滚动 RT；反向靠 UV 翻转 |

连通 / 邻格判定（对齐宿主 `DoorBlock` / `WoodBlock`）：

```csharp
BlocksManager.Blocks[terrain.GetCellContentsFast(x, y, z)] is LogisticsStorageUnitBlock
```

`LogisticsStorageUnitBlock` **不**与 Transfer / 输送带共用 Index：存储是全向立方体容器语义；输送带为定向连续物流；Transfer 预计是定向搬运。仅贴图格可相邻排布在同一图集（输送带用独立贴图路径）。

## 复用输送带外观

别的方块想在外观上「嵌入」一段带子（机器进出料口等），**不要**自己加载 `Models/ConveyerBelt` 或复刻 reverse/powered 的 UV 翻转，直接在 `GenerateTerrainVertices` 里调：

```csharp
ConveyerBeltDrawingManager.GenerateBeltVertices(
    generator, geometry, x, y, z,
    ConveyerBeltBlock.MakeData(shape: 0, rotation: 1, reverse: 0, powered: 1),
    transform: Matrix.CreateTranslation(0f, -0.25f, 0f)); // 可选：格内下沉 / 偏移
```

带子进滚动贴图子集、随全局相位动；`powered` 决定采静区还是滚动半区，`reverse` 决定滚动方向。手持 / 物品栏走 `ConveyerBeltDrawingManager.DrawBelt`。写法参照 IE2 `WireDrawingManager.GenerateWireVertices`。

注意：这只是**外观**复用。嵌入的带子不会进 `BeltGroup`，不参与运物、动力与交接；要真运物仍需放真实输送带方块。
